# Epic 2 Decisions — Academic Setup & User Management

## 1. Can a user's role change after account creation?

**Chosen answer:** No. Roles are immutable after creation. Admin can update profile information and activation status, but role changes require a correctly created replacement account and preservation of the old account's history.

## 2. How should classes and courses be modeled?

**Chosen answer:** Use one `ClassCourse` entity with required, unique `Name` and `Code`. Do not create separate Class and Course models.

## 3. Should Subjects be explicitly linked to Classes/Courses before teacher assignment?

**Chosen answer:** No. Subjects are global. A valid Class/Course + Subject combination is established through a Teacher Responsibility, avoiding an unnecessary curriculum-mapping table.

## 4. What happens when a student is removed from a Class/Course?

**Chosen answer:** End the enrollment rather than deleting it. Block new or unsubmitted work from that Class/Course, while preserving the student's own past submissions and graded results.

## 5. Can more than one active teacher own the same Class/Course + Subject combination?

**Chosen answer:** No. Exactly one active Teacher Responsibility exists for each Class/Course + Subject combination.

## 6. How are initial passwords delivered for newly created accounts?

**Chosen answer:** The system generates a temporary password and shows it to Admin once. Admin shares it privately through the institution's existing channel; email/SMS delivery is not part of the application.

## 7. How are passwords reset?

**Chosen answer:** Admin resets a password by generating a new temporary password and seeing it once. Self-service password recovery is deferred.

## 8. Which user details may Admin edit?

**Chosen answer:** Admin may edit full name, optional email, and institutional ID. Role stays immutable and activation stays a separate action. Email is optional contact information and must be unique when supplied.

## 9. How are institutional IDs assigned and corrected?

**Chosen answer:** Admin enters the institution's existing, globally unique ID when creating an account. Admin may later correct it with uniqueness validation and an audit record. Internal GUIDs preserve academic history.

## 10. Must a new user change the temporary password?

**Chosen answer:** Yes. Newly created Teacher and Student accounts must change their temporary password before normal access. Seeded demo accounts are exempt for evaluator convenience.

## 11. What is the account source of truth?

**Chosen answer:** `ApplicationUser` is the sole source of truth. Remove the unused Domain `UserAccount` and `UserRole` models; academic entities use immutable user IDs.

## 12. Should academic records store profile snapshots?

**Chosen answer:** No. Academic records store immutable user IDs and display current profile name/email. Do not duplicate name/email snapshots on every academic record.

## 13. Where is academic authorization enforced?

**Chosen answer:** Use controller role policies, application-service resource/scope checks, and PostgreSQL uniqueness/integrity constraints. Never rely only on frontend visibility.

## 14. How are Classes/Courses and Subjects retired?

**Chosen answer:** Archive them rather than deleting them. Archived records cannot be used for future academic setup but retain historical records.

## 15. How are Teacher Responsibilities removed and preserved?

**Chosen answer:** End them as temporal records with `AssignedAt`, `RevokedAt`, and `RevokedByUserId`; never delete them. Reassignment creates a new record.

## 16. Where do audit records live?

**Chosen answer:** Persist focused account-audit events in PostgreSQL for account creation, profile/ID changes, activation changes, and password resets. Store actor, target, timestamp, and a safe change summary.

## 17. Should demo credentials be visible in the login UI?

**Chosen answer:** Add a development/demo-only credential panel later. It may show or autofill seeded demo credentials, but it must never expose real production credentials.
